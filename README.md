# Фото для документов и подпись Nexcel

Браузерный сервис [photo.nexcel.kz](https://photo.nexcel.kz/) готовит фото для удостоверения личности РК и Green Card DV, а также извлекает подпись из фотографии. Сервис не является официальным. Решение о приёме документов принимает соответствующий орган.

## Локальный запуск

Нужен Node.js, поддерживаемый установленной версией Vite: `^20.19.0 || >=22.12.0`. В этом релизе проверен Node.js 24.21.0.

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite. Для production-сборки:

```sh
npm run build
npm run preview
```

Публикация — Cloudflare Pages, ветка `master`, команда сборки `npm run build`, каталог `dist`. Подробности в [DEPLOY.md](DEPLOY.md). Папки `tests`, `scripts` и `docs` не входят в публикуемый каталог.

## Команды проверок

| Команда | Назначение |
| --- | --- |
| `npm test` | Геометрия, JPEG, юнит-тесты, production-сборка и все e2e |
| `npm run test:e2e` | Chromium, работа фото и подписи, доступность, CSP, HEIC, языковые адреса и SEO |
| `npm run check:links` | Доступность официальных ссылок; предупреждения внешних серверов нужно оценить отдельно |
| `npm run calibrate` | Детектор и реальная обрезка каждого локального селфи для `kz_id` и `dv`; таблица и предложение коэффициентов |
| `npm run export:kz` | Экспорт всех пар RU/KZ для носителя в `docs/kz-review.csv` |
| `npm run check:production-deps` | Проверка графа модулей production-сборки на пять пакетов, отмеченных audit |
| `npm audit` | Полный аудит, включая инструменты сборки |
| `npm audit --omit=dev` | Аудит зависимостей приложения |

Браузерным тестам нужен Chromium: `npx playwright install chromium`. На Windows также подойдут установленный Chrome/Edge; путь можно задать переменной `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Тестовые камеры используют локальное синтетическое видео. Это не проверка физической камеры телефона.

## Калибровка обрезки

Папка `tests/fixtures/selfies/` создаётся командой `npm run calibrate` и исключена из Git целиком, включая фото, разметку и отчёт. Не помещайте снимки в `public` или `dist` и не используйте `git add -f` для этой папки.

1. Положите туда 5–10 собственных или предоставленных с согласия человека селфи: светлые и тёмные волосы, густая/объёмная причёска, обычные очки, разное освещение и разные расстояния от камеры. По возможности используйте несколько телефонов. Форматы — JPEG, PNG, WebP; HEIC сначала сохраните как JPEG.
2. Запустите `npm run calibrate`. Скрипт открывает локальный браузер без видимого окна, использует **тот же `detectFaceInBitmap` и `cropFace`**, что сайт, и печатает строки для обоих документов. Внешние запросы и отправка фотографий по HTTP блокируются. При пустой папке он печатает инструкцию и завершает работу с кодом 0.
3. Откройте созданный локальный `tests/fixtures/selfies/calibration-review.html`. Нажмите на верхнюю точку головы с учётом волос. Проверьте подбородок, отмеченный детектором; при необходимости укажите его вручную. Выберите обычные/густые волосы и подтвердите видимость макушки и проверку разметки.
4. Скачайте `annotations.json` из этой страницы в ту же папку с селфи, затем повторите `npm run calibrate`.
5. Смотрите таблицу и `calibration-report.json`: файл, документ, измеренная доля головы, диапазон, смещение центра лица по горизонтали, обрезание макушки/подбородка и ошибки. Диапазоны: РК 70–80%, DV 50–69%. Знак `—` означает отсутствие достоверного измерения, а не нулевой размер головы.

Landmark 10 — ориентир лба, а не подтверждённая макушка. Измерять голову через тот же `HEAD_TOP_FACTOR`, которым строится кадр, нельзя: это всегда возвращало бы целевые 75%/59,5%. Поэтому реальный `head%` появляется только при независимо отмеченной и подтверждённой макушке. Непроверенная или невидимая макушка не участвует в рекомендации. Ошибка создания кадра также исключает строку из рекомендации.

Измерение использует преобразование исходных точек в координаты итогового кадра: `head% = 100 × (yПодбородок − yМакушка) / высотаКадра`. Коэффициент по фото — отношение измеренной высоты головы к высоте лица между landmarks 152 и 10 после выравнивания. Если большинство достоверных результатов вне диапазона, предлагается медиана коэффициентов отдельно для обычных и густых волос, а также множитель густых волос к обычным. Для группы без разметки значение не выдумывается. Меньше пяти проверенных фото явно помечается как малая выборка.

**Скрипт не меняет `HEAD_TOP_FACTOR`.** Менять его в `src/lib/crop.js` следует только после прогона реальных фотографий, проверки разметки и сравнения результата повторного прогона. Сейчас реальная калибровка не завершена: селфи не предоставлены.

Отдельную локальную подвыборку можно проверить через `npm run calibrate -- --input tests/fixtures/selfies/subset`. Отчёт и HTML с фото будут созданы внутри выбранной папки; она также должна оставаться вне Git и публикации. Тесты работоспособности CLI используют отдельный тестовый портрет, без подтверждённой макушки: это не калибровка реальных селфи и не основание менять коэффициент.

## Правила и официальные источники

Карточки РК и DV находятся в `src/content/requirements.js`, подпись — в `src/components/signature/rules-copy.js`, размеры экспорта — в `src/presets.js`. Тексты интерфейса: `src/i18n.js`, `src/content/photo-copy.js`, `src/components/signature/copy.js`; служебные сообщения релиза — `src/content/release-copy.js`.

- РК: [Приложение 2 на zan.gov.kz](https://zan.gov.kz/client/#!/doc/140840/rus/158), [официальный приказ МВД РК № 267 на Әділет](https://old.adilet.zan.kz/rus/docs/V2000020192).
- DV: [Photo Requirements на travel.state.gov](https://travel.state.gov/content/travel/en/us-visas/visa-information-resources/photos.html).
- Результаты сверки DV: [docs/dv-rules-review.md](docs/dv-rules-review.md).

При изменении приказа или требований откройте действующий официальный текст и нужный раздел приложения. Зафиксируйте дату, ссылку, подтверждённые значения и статус каждого пункта. Меняйте только подтверждённые расхождения, согласованно в карточках и настройках экспорта. Непроверенные значения не заменяйте предположениями. После изменения обновите отчёт, экспорт RU/KZ и тесты. Переводы остаются **на проверку носителем** до его отметки.

`docs/kz-review.csv` содержит UTF-8 с BOM, разделитель — запятая. Колонки: ключ, русский текст, казахский текст, статус, комментарий. Поля человека оставлены пустыми. Команда откажется перезаписывать CSV с заполненными отметками. Для осознанной замены после сохранения результатов отдельно: `npm run export:kz -- --replace`. Существующие KZ-тексты автоматически не переписываются.

## Конфиденциальность и границы проверки

Фото, подписи, выделение фона и детекция лица обрабатываются в браузере. Приложение не отправляет изображения на сервер и не добавляет аналитику с изображениями. Сервер отдаёт код, шрифты и модели; это не загрузка пользовательского фото. Обновление страницы начинает новый сеанс. Скачанные файлы остаются на устройстве пользователя.

HEIC/HEIF не декодируется: показывается сообщение «Сохраните как JPEG или снимите на камеру сайта». JPEG, автоматически преобразованный галереей телефона, принимается по фактическому содержимому. Физические устройства и конкретные камеры необходимо проверить человеком по [docs/device-test-checklist.md](docs/device-test-checklist.md). Эмуляция и виртуальная камера не заменяют этот чек-лист.

Русские адреса: `/`, `/signature/`. Казахские: `/kk/`, `/kk/signature/`; у них собственные статические canonical, OG-метаданные и взаимные `hreflang="ru"`/`hreflang="kk"`. Кнопка языка меняет адрес. Параметры `?lang=kk`/`?lang=kz` поддерживаются как старые ссылки и переводят интерфейс на казахский адрес.

## Подготовка релиза

Перед публикацией выполните тесты, сборку, audit и проверку production-зависимостей. Результаты и границы пяти high описаны в [docs/security-notes.md](docs/security-notes.md). Не публикуйте Vite dev/preview как production-сервер и не понижайте версии принудительно ради зелёного audit.

Мобильный Lighthouse 13.6.0 для обеих страниц можно повторить командой ниже, заменив адрес и имя отчёта:

```sh
npx lighthouse@13.6.0 https://photo.nexcel.kz/ --only-categories=performance,accessibility,best-practices,seo --output=json --output-path=test-results/lighthouse-photo.json --chrome-flags="--headless=new"
```

Для Windows при необходимости добавьте `--chrome-path="C:\Program Files\Google\Chrome\Application\chrome.exe"`. Цель — все четыре категории не ниже 90. Это лабораторный замер, не измерение реального телефона. Итоговые результаты — в `docs/release-readiness.md`.
