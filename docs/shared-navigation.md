# Подключение photo.nexcel.kz к общему меню

Публичный источник: https://nexcel.kz/shared/nav.json. Редактируемый справочник — `content/navigation.json` в репозитории `Tarlan2006/Nexcel_website`, ветка main. Дублирующие списки услуг, компании, контактов и соцсетей удалены из `src/siteLinks.js` фотосервиса.

`scripts/sync-shared-nav.js` выполняется перед build и dev. Он получает актуальные JSON и логотип по HTTPS, проверяет структуру v1, RU/KK поля, ссылки и отсутствие повторов. Сохранённые снимки включаются в JS-сборку. Логотип включён как image data URL. Браузер пользователя загружает только ресурсы фото-сайта, изменения CSP не требуются. Пользовательские изображения обрабатываются прежним локальным пайплайном.

Снимки: `src/content/shared-nav.json`, `src/content/shared-logo.json`. Это публичные фирменные данные; личных фотографий и секретов в них нет. При ошибке сети или неверном JSON публикация останавливается, старый рабочий сайт остаётся доступен. Для локальной работы без сети есть явный `SHARED_NAV_OFFLINE=1`; автоматический переход на устаревшие данные не применяется.

`src/lib/shared-navigation.js` строит списки непосредственно из JSON. Служебные ключи известных адресов нужны для существующих KZ-переводов; неизвестная новая услуга также появляется автоматически. Когда `kk` заполнен, используется он. Пока основной сайт только RU, для известных элементов сохраняются KZ-переводы фотосервиса, для новых — RU из источника. Самостоятельных новых переводов не добавлено.

Шапка и футер сохраняют свои CSS-классы, размеры, сетку, язык и поведение. Добавлены существующие на основном сайте услуги, включая создание сайтов и фото; общие сведения футера приведены к текущему основному справочнику. Локальные правила РК/DV/подписи и пояснения о конфиденциальности остаются в своих компонентах.

Автоматическая цепочка после ручной настройки: правка справочника основного сайта → генерация JSON/partials → push main → проверка и публикация → workflow сверяет публичный JSON → один POST на PHOTO_DEPLOY_HOOK → сборка master фотосервиса получает новый JSON → публикация обновлённого меню.

Вручную нужно создать Deploy Hook [Cloudflare Pages-проекта photo-nexcel](https://dash.cloudflare.com/a947507fcdc5eee5d2165a42f17037ff/pages/view/photo-nexcel) для master. Сохраните его URL как Actions secret PHOTO_DEPLOY_HOOK в репозитории Nexcel_website. Без секрета основной workflow пропускает уведомление успешно. Реальный вызов hook без предоставленного секрета не проверялся. Проект подтверждён успешной проверкой Cloudflare Pages для коммита 03baf0b; отдельный одноимённый Worker создавать не нужно.
